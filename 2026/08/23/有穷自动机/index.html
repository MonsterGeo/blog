嵌入式系统形式化

定义：任务 RTOS中的任务本质是一段无限循环的C语言函数，每一个任务负责一部分系统之内的功能。并且每个任务有自己的栈空间和运行状态。

我们可以将一个任务抽象为一个有限状态机(FSM)，一个状态它可以是多个或一个的任务集合。所以，当我们简单的说一个系统是稳定与否，就是在评判一个FSM是否在某个时刻后依然是正确的输出。

定义：有限状态机

一个有穷自动机包括：

  • 一个有穷的状态集合，我们记做Q
  • 一个有穷的输入符号集合，我们记作Σ
  • 一个转移函数，转移函数以一个状态和一个输入符号作为变量，返回一个状态。我们记作δ，在非形式化表示自动机的图中，我们可以在状态的和状态上的边使用箭头来标记表示δ。
  • 一个初始状态。它也是Q中的一个状态。
  • 一个终结状态或接受状态的集合F，满足F ⊆ Q

我们使用FSM表示有穷状态机。一个FSM最少满足上述五个部分。使用如下五元组记号讨论DFA：

A = (Q, Σ, Δ, q0, F)

其中q0是初始状态。

我们可以简单的使用一个有向图表示DFA。当然有了图就能用邻接矩阵表示。

如果把δ函数稍微修改，那么我们可以把DFA转为NFA。

NFA(非确定状态机)的转移函数δ是以一个状态和一个输入作为变量并返回一组Q的子集合，也就是说，确定型状态机它是状态跳转，而NFA告诉你某个节点接收一个输入会产生多少个可能的状态集合。

定义：死状态 一个死状态满足下述2个条件 + 陷阱性：系统一旦进入这个状态，无论后续输入的任何事件/信号，系统都无法离开该状态：∀a ∈ Σ, δ(s, a) = s。 + 非接收性：该状态不是系统的合法终止状态，即s ∉ F，并且该状态下系统无法完成预期的业务和功能。

因此，第一个考察稳定性的功能就是嵌入式系统不会进入死状态。通过拓展一般死锁定义，我们可以将其和死状态联系起来。死锁指的是多任务下，任务因为争夺资源互相等待对方释放资源而造成的阻塞现象。那么这种阻塞就等价于我们的死状态的定义。

另一种可能的是状态融合(State Fusion Fault)。它指的是对互斥的状态在某种情况下发生了两种或两种以上的状态激活。

定义：状态激活 给定一组状态Q = {q1, q2, ⋯, qn}，对i = 1, 2, ⋯, n，qn ∈ {0, 1}，其中qi = 1表示状态激活，qi = 0表示状态未激活。

定义：非法融合(state fusion fault) 那么一个健壮的前提是满足如下2条要求 + 绝对互斥性：在任意时刻t，系统满足：

$$ \sum_i p_i(t) = 1 或者 p_A(t) \And P_B(t) = 0 $$

其中$\And$是and运算。

  • 状态融合故障：某时刻t下，输出等于f(SA) + f(SB)，其中SB是事件B。f是输出函数。

当我们说一个状态机是非法的时候，它不满足上述2个条件之一。

一个确定性状态机FDA在接收一串数据后，必定会输出正确的状态，为此我们使用终态集合F定义强收敛性，我们说一个状态机是收敛的，那么它是无活锁1且可

定义如下：

定义：收敛性 对状态机A = (Q, ∑,δ, q0, F)，我们说其是强收敛的，那么他首先满足无活锁且必达终态。

  • 稳定性：系统从任意可达状态q ∈ Reach(q0)出发，在对任意可能产生的输入序列w ∈ ∑*，都存在一个有限长度的前缀w′ ≼ w，使得输出落入终态集F

∀q ∈ Reach(q0), ∀w ∈ ∑w, ∃k ∈ ℕ, s.t  δ(q, wk) ∈ F

其中wk是长为k的输入串.

  • 时序性：我们定义更强的收敛约束，对时间t，我们说系统是k−步收敛的，当且仅当在时间常数Tmax < ∞下，使得任意可达状态q转移到F的累计耗时满足

supq ∈ Reach(q0)|Tk − Tmax| < ϵ

Tk是实际输入k串的结果，ϵ > 0

  1. 可以比喻为高频噪声对系统的干扰↩︎
